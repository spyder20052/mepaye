Introduction

L’API est REST/JSON. URL de base : https://mepaye.com/api/v1.

  1. Créez un paiement (POST /payments) : vous recevez une payment_url.
  2. Redirigez l’acheteur vers cette adresse, la page hébergée pay.mepaye.com.
  3. L’acheteur paie. Les fonds arrivent dans votre wallet, commission mepaye de 5 %.
  4. Votre serveur reçoit le webhook signé payment.succeeded : vous livrez.

L’acheteur ne voit que pay.mepaye.com. Aucun agrégateur n’est exposé.

Authentification

Créez une clé dans le menu Développeur. La vérification d’identité (KYC) est obligatoire. Chaque requête porte l’en-tête :

HTTP
Authorization: Bearer mp_live_xxxxxxxx
PréfixeEnvironnement
mp_live_Encaissement réel
mp_test_Simulation, voir Mode test

La clé porte le scope payments:write. Limite : 100 requêtes par minute et par clé.

Ne l’exposez jamais côté client. Appelez l’API uniquement depuis votre serveur.

Créer un paiement

POST/api/v1/payments

En-têtes : Authorization, Content-Type: application/json et Idempotency-Key, obligatoire.

Corps

ChampDescription
amountEntier, en minor units (5000 = 5 000 XOF). Minimum 100, sans plafond.
currencyLa devise de votre boutique.
externalReferenceVotre référence de commande, renvoyée dans le webhook.
buyer optionnelname, email, phone, country (ISO-2). Préremplis et modifiables sur la page.
curl -X POST https://mepaye.com/api/v1/payments \
  -H "Authorization: Bearer mp_live_xxx" \
  -H "Idempotency-Key: cmd_8f2a1c" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 5000,
    "currency": "XOF",
    "externalReference": "CMD-2026-0142",
    "buyer": {
      "name": "Awa Diop",
      "email": "awa@exemple.com",
      "phone": "+221770000000",
      "country": "SN"
    }
  }'
const res = await fetch("https://mepaye.com/api/v1/payments", {
  method: "POST",
  headers: {
    "Authorization": "Bearer " + process.env.MEPAYE_API_KEY,
    "Idempotency-Key": order.id, // votre référence unique
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    amount: 5000,        // minor units (5 000 XOF)
    currency: "XOF",     // = devise de votre boutique

const payment = await res.json();

redirect(payment.payment_url);

Réponse

JSON
{
  "id": "cmqz19fk40008jr1hxlyy6065",
  "status": "pending",
  "test": false,
  "payment_url": "https://pay.mepaye.com/checkout/cmqz19fk40008jr1hxlyy6065",
  "externalReference": "CMD-2026-0142",
  "idempotent_replay": false
}

Redirigez l’acheteur vers payment_url.

Idempotence. Renvoyez la même Idempotency-Key, par exemple l’id de votre commande : vous obtenez le même paiement (idempotent_replay: true). Jamais de double encaissement, même si vous rejouez la requête.

Webhooks

Configurez votre URL, votre secret et vos événements dans Développeur › Webhooks. Deux événements, en test comme en live : payment.succeeded et payment.failed. Le champ test du contenu les distingue.

HTTP
POST https://votre-site.com/webhooks/mepaye
X-Mepaye-Event: payment.succeeded
X-Mepaye-Signature: sha256=2f1a…c9
X-Mepaye-Delivery: <id>

{
  "event": "payment.succeeded",
  "data": {
    "id": "cmqz19fk40008jr1hxlyy6065",
    "externalReference": "CMD-2026-0142",
    "status": "PAID",
    "amount": 5000,
    "currency": "XOF",
    "test": false,
    "created_at": "2026-06-29T09:45:30.000Z"
  },
  "deliveredAt": "2026-06-29T09:45:31.200Z"
}

Nous réessayons jusqu’à 5 fois (délai exponentiel) tant que votre endpoint ne répond pas en 2xx. Après 20 échecs consécutifs, le webhook est désactivé.

Répondez 200 rapidement, et traitez chaque réception de façon idempotente : un même X-Mepaye-Delivery peut arriver plus d’une fois.

Vérifier la signature

Chaque webhook porte X-Mepaye-Signature: sha256=<hex> : un HMAC-SHA256 du corps brut de la requête, avec le secret de votre webhook. Vérifiez-le avant tout traitement, sinon n’importe qui pourrait forger un événement.

const crypto = require("crypto");

app.post("/webhooks/mepaye", express.raw({ type: "*/*" }), (req, res) => {
  const raw = req.body; // corps brut (non parsé)
  const received = req.header("X-Mepaye-Signature"); // "sha256=..."
  const expected =
    "sha256=" + crypto.createHmac("sha256", process.env.MEPAYE_WEBHOOK_SECRET)
      .update(raw).digest("hex");

  const ok =
    received &&
    crypto.timingSafeEqual(Buffer.from(received), Buffer.from(expected));
  if (!ok) return res.status(401).end();

  const { event, data } = JSON.parse(raw);
  // event = "payment.succeeded" | "payment.failed" ; data.test = mode test
  // → livrez le produit pour data.externalReference
  res.status(200).end(); // répondez vite en 2xx
});
$raw = file_get_contents("php://input");
$received = $_SERVER["HTTP_X_MEPAYE_SIGNATURE"] ?? "";
$expected = "sha256=" . hash_hmac("sha256", $raw, getenv("MEPAYE_WEBHOOK_SECRET"));

if (!hash_equals($expected, $received)) {
  http_response_code(401);
  exit;
}
$payload = json_decode($raw, true);
// $payload["event"], $payload["data"]["externalReference"], $payload["data"]["test"]
http_response_code(200);

Calculez le HMAC sur le corps brut reçu, sans le re-sérialiser, et comparez en temps constant (timingSafeEqual ou hash_equals).

Mode test

Une clé mp_test_ crée un paiement de test : la payment_url ouvre une page « Mode test » avec deux boutons, Simuler un paiement réussi et Simuler un échec. Aucun argent réel, aucun agrégateur, vos ventes restent intactes.

Le webhook correspondant est émis avec test: true. Testez votre intégration de bout en bout avant de passer en mp_live_.

Voir la page Mode testpay.mepaye.com, telle que l’acheteur la voit
